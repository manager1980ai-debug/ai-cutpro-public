# A1: безопасная замена исходного DXF (23.11.2026)

## Проверенный объём реализации

В `CutProjectDxfWorkspaceCodec.ReplaceSource(project, replacementAsciiDxf, discardExistingAssignments)` предусмотрены два режима:

1. При **побайтово одинаковом тексте DXF** существующий, предварительно валидированный проект возвращается без изменения технологических назначений.
2. При **изменённом DXF** замена запрещена, пока вызывающий код явно не передаст `discardExistingAssignments: true`. После этого создаётся новый DXF workspace с **пустыми** четырьмя реестрами технологических назначений. Новый исходный документ, лист, единицы измерения и итоговый проект валидируются до возврата результата; прежняя модель проекта не изменяется.

**Ни индексы объектов, ни геометрическое сходство не являются доказательством сохранности технологических назначений.** Автоматического переноса и сопоставления операций между различными DXF нет. При отказе вызывающему коду запрещено применять частично обновлённое состояние.

## Регрессионные проверки

Тесты ядра проверяют запрет несанкционированной замены, сохранение назначений на идентичном тексте, полное обнуление назначений после подтверждения, сериализацию/повторное открытие нового проекта, неизменность старого проекта и отказ при неверных единицах.

## Осталось

- **Код интерфейса добавлен:** кнопка выбора нового ASCII DXF, проверка до подтверждения, отдельное окно с предупреждением **потери всех прежних назначений**, отмена без изменения проекта, обновление текущего проекта после подтверждения. После замены требуется вручную сохранить JSON. Проверка настоящего file-picker остаётся неподтверждённой до интерактивного Windows-сеанса; GUI smoke для подтверждения ещё требуется.
- Разработать отдельный **проверяемый** перенос назначений после геометрических правок с независимой идентификацией элементов и показом результата до подтверждения. До этого все изменённые источники допускают только явный сброс.
- Выполнить GUI smoke и реальные интерактивные OS file-picker проверки. Hosted runner не подтверждает работу нативных диалогов.
- Провести B3 стресс-тесты на независимом DXF-корпусе, затем итоговую приёмку этапа 2.

Это не CAM, не G-code и не разрешение на физическое управление станком.

## Дополнительные проверки 24.11.2026

В диалоге подтверждения замены теперь указываются **проверенные количества DXF-объектов до и после**, полученные из заново загруженных валидированных документов. Это информационное сравнение, не автоматическая привязка технологических операций и не аттестация геометрии.

В синтетический B3-корпус добавлены проверки ровно 1000 DXF-объектов (допустимый верхний предел) и 1001 объекта (строгий отказ без усечения). Результаты нужно подтверждать GitHub Actions для финального коммита, прежде чем отметить тесты пройденными. Нативные системные диалоги пока **не проверены**.

## B3: численные границы сохраняемого DXF (24.11.2026)

Отдельно от функции диагностического предпросмотра проверяются координаты и радиусы в **встраиваемом в JSON проекта DXF**. Геометрия с модулем координаты или радиуса более **1 000 000 мм** отклоняется до изменения текущего проекта. Величина согласована с ограничением по умолчанию в `GeometryPreflight`. Это защитный предел для численной устойчивости, **не подтверждение производственной точности** и не замена анализа пересечений.

Регрессии охватывают ровно 1 000 000 мм, выход за предел в обе стороны, экстремальное конечное число `1e308`, слишком большой радиус ARC и отсутствие изменений исходных технологических назначений при отказе. Для соответствующего коммита требуется успешный CI Windows/Linux/macOS.
